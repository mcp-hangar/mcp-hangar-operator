**controller:** the operator reads core's version from `GET /api/system/` on start, on every reconnect and once a minute, and refuses a core older than 2.27.0, the first with `ssrf.trusted_networks`, which every registration it makes needs. Against such a core it registers no `MCPServer`, starts no pod for a new container-mode one and delivers no L7 policy. It reports the refusal once for the whole operator: a Warning Event `CoreIncompatible` regarding the operator's Pod, an error log line and the new `mcp_operator_core_compatibility{state}` gauge. An `MCPServer` reports `Ready=False` with reason `CoreIncompatible` and an `MCPEgressPolicy` reports `L7Delivered=False` with that reason; neither goes `Degraded`. A version the operator cannot read, for example because its API key lacks `mcp_servers:read`, holds it the same way with reason `CoreVersionUnknown`. NetworkPolicies and backstops are applied as before. The `hangar_client_*` metrics label the version read `system_info`, which was `capabilities`
